日本語の Web フォントは重い。これは工夫でどうにかなる差ではなく、桁の問題だ。

ラテン文字のフォントは 26 文字 × 大小 + 数字と記号で、可変フォントでも 30 KB 前後に収まる。
日本語は常用漢字だけで 2,136 字、実用的には 6,000 字以上を持つ必要があり、
素の woff2 で 1〜5 MB になる。

## サブセット化は解決策ではない

「使う文字だけ切り出せばいい」という話になるが、ブログでは**次に何を書くか分からない**。
ビルド時に全記事をスキャンして使用文字を集める手はあるが、記事を 1 本足すたびに
フォントファイルのハッシュが変わり、全ページのキャッシュが飛ぶ。

Google Fonts の日本語サブセットのように 100 個以上のファイルに分割して
`unicode-range` で必要な断片だけ落とす方法もある。これはよく出来ているが、
それでも 1 ページで 10〜20 リクエスト、数百 KB になる。

## 何を捨てて、何を残したか

このサイトでは Web フォントをゼロにした。本文も見出しも OS のシステムフォントで組む。

```css
--font-sans: system-ui, -apple-system, "Segoe UI", "Hiragino Sans",
  "Hiragino Kaku Gothic ProN", "Yu Gothic", Meiryo, sans-serif;
```

問題は、これだけだと「どこかで見たサイト」になることだ。フォントで個性を出せない以上、
残った手札は**組み方**しかない。やったのは次の 3 つ。

- **大きい文字を思い切り詰める。** 見出しに `letter-spacing: -0.045em` と `font-weight: 800`
  を当てる。システムフォントでも、大きく重く詰めれば十分に強い。
- **`palt` を見出しだけに効かせる。** 詰め組みが効くのは大きい文字で、本文に当てると
  かえって読みにくい。`font-feature-settings: "palt" 1` は見出しに限定した。
- **数字と英字をモノスペースに逃がす。** 日付・サイズ・タグを等幅で組むと、
  和文の面と対比が生まれて画面が締まる。`font-variant-numeric: tabular-nums` で桁も揃う。

## 本文の行間

日本語は英語より行間を空けたほうが読める。仮名と漢字で字面の大きさが違うぶん、
行が詰まると塊に見えるからだ。このサイトは `line-height: 1.9` にしている。
英語圏のデザインシステムをそのまま持ってくると 1.5 前後になりがちで、これは和文には狭い。

結果として、フォントの読み込みが 0 バイト、FOUT も FOIT も起きない。
一番速い Web フォントは、読み込まない Web フォントだった。
